## Scope

The completion target is a full, polished global strategy and turn-based tactical game in Unreal Engine 5.8.2 or newer. A playable subset, prototype, or vertical slice does not satisfy completion.

OpenXcom upstream commit `630130c5c9ac236b9e1d8496005fb23e84e397ca` is retained as a catalog of genre-system breadth. UEGT is a modified, original implementation rather than an exact source, content, interface, save-format, or audiovisual port. Full scope means every major player-facing capability has an original UEGT counterpart and release-quality verification; it does not mean copying protected implementation or content.

The initial toolchain target is the locally installed Unreal Engine 5.8.2 build, changelist 56702186. The project is intended for non-profit distribution, but all release gates still apply.

## Independent implementation boundary

- `Source/` is original MIT-licensed UEGT code.
- Unreal targets must not include, compile, link, load, or package OpenXcom source, objects, libraries, rulesets, translations, or bundled media.
- Original UEGT specifications, names, data schemas, UI, narrative, art, audio, and rules replace exact compatibility.
- The legacy GPL tree remains outside the Unreal build as a historical system-coverage reference only.
- This boundary is an engineering control, not a claim of legal clean-room certification. Counsel review remains a release gate.

The prior direct-port licensing analysis is retained in [LICENSE-CLEARANCE.md](LICENSE-CLEARANCE.md). It applies if direct GPL source translation is ever reconsidered.

## Architecture

- `UEGTCore` owns deterministic strategic and tactical domain logic, original rules models, save data, seeded simulation services, and automation tests. It must not depend on frame rate or presentation state.
- `UEGTGame` owns Unreal lifecycle integration, worlds, actors, input, UI, audio, rendering, accessibility, and adapters into `UEGTCore`.
- Game-state changes occur through explicit commands and events so saves, replays, AI, UI, and tests observe the same deterministic simulation.
- Every completed subsystem requires boundary tests, integration tests, and player-visible acceptance evidence appropriate to its risk.
